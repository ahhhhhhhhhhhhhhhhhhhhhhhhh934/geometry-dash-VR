# Geometry Dash VR

An unofficial, original VR rhythm-platformer project targeting Meta Quest 3 and Horizon OS.

## Project status

**Prototype foundation — not yet a playable game.** This repository is the dedicated home for all Geometry Dash VR development. It is separate from the Geode Versus Mode mod.

## Target platform and build format

Meta Quest 3 runs **Horizon OS**, which is based on the Android Open Source Project (AOSP). For this project, Unity builds an Android application package:

- Development output: `.apk`
- Target: Android / Meta Quest 3
- XR runtime: OpenXR
- Rendering: stereoscopic immersive VR

The APK is generated by Unity when the project is built. We do **not** need a pre-existing APK to write the game. The APK is the installable output used to test the game on the headset.

## Technology

- Unity 6.0.66f2
- Unity OpenXR Plugin 1.15.1
- Unity XR Plug-in Management
- Unity Input System
- Android Build Support (SDK, NDK, OpenJDK)
- Meta Quest / Horizon OS

Meta's current Unity guidance recommends Unity OpenXR for new projects. The legacy Oculus XR Plugin is deprecated. The Meta XR SDK can be added for Meta-specific capabilities when the project needs them.

## Set up the Unity project

1. Install Unity Hub and **Unity 6000.0.66f2**.
2. In Unity Hub, add **Android Build Support**, including Android SDK & NDK Tools and OpenJDK.
3. Open this repository's root folder in Unity Hub.
4. Let Unity Package Manager resolve the dependencies in `Packages/manifest.json`.
5. In Unity, open **Edit > Project Settings > XR Plug-in Management** and install XR Plug-in Management if prompted.
6. Enable **OpenXR** for the Android build target. Enable the appropriate Meta Quest / Meta XR OpenXR feature group when available.
7. In **File > Build Profiles**, enable the **Meta Quest** platform. If that platform is not offered by the installed editor, use Android as the build target.
8. In the Unity Editor, run **Geometry Dash VR > Create Prototype Scene**. This creates `Assets/Scenes/VRPrototype.unity` and adds it to Build Settings.
9. Enable OpenXR for Android and configure the Quest controller interaction profile. The generated scene contains a tracked headset/controller rig and a basic auto-run obstacle course.
10. In Play Mode, use controller trigger to jump (or Space in the editor) and the left controller thumbstick to steer. This is an early prototype; collision, comfort, and device behavior still need testing.
11. Add the scene to the Meta Quest Build Profile if it is not already listed. Connect a Quest headset through an eligible developer setup and use Unity's **Build** or **Build And Run** action. Unity produces an APK.

For Meta-specific hand tracking, interaction, passthrough, or platform APIs, add the Meta XR SDK packages through Unity Package Manager and use the Meta Project Setup Tool to check the project configuration. Do not add platform-specific SDKs until a feature needs them.

## Installing and testing the APK

The APK is installed on the headset for local testing. Meta documents deployment through Meta Quest Developer Hub or Android Debug Bridge (ADB). A physical headset, a data-capable USB connection, and the appropriate developer setup are needed.

**Account eligibility note:** Meta's current developer-mode documentation lists an 18+ requirement for enabling developer mode. A qualifying adult account holder must handle developer-account and device setup. Do not bypass age or account requirements.

A simulator can help with early scene iteration, but the final experience must be tested on a physical Quest device.

## Locomotion prototype

The initial hand-push script is an experimental starting point, not a complete Gorilla Tag implementation. It uses tracked hand movement while the grip button is held and the hand is touching a surface. Comfort options and collision testing are required before treating it as production-ready.

## Important project boundaries

- Use original code, art, music, levels, and branding.
- Do not bundle proprietary Geometry Dash or RobTop game files.
- Any third-party code adopted later must retain its license and attribution.
- Globed cross-play is a future research goal, not implemented.
